# 공식 출처 검증

현재 법률값을 계산에 사용하거나 신고기한을 확정하기 전에 적용한다.

## 출처 우선순위

1. 국가법령정보센터: 법률·시행령·시행규칙 원문, 시행일, 연혁
2. 국세청·홈택스: 공식 신고 안내, 서식, 집행기준, 예규·해석
3. 기획재정부: 개정 설명, 입법 자료, 공식 발표
4. 국외 쟁점: 해당 국가 세무당국과 조세조약 원문

블로그, 카페, 뉴스, 광고성 세무법인 자료는 쟁점 발견에만 사용할 수 있고 결론의 유일한 근거가 될 수 없다.

## 필수 기록 필드

| 필드 | 기록 내용 |
|---|---|
| source_id | 사건 내 고유 출처 ID |
| 법령명/자료명 | 정식 명칭 |
| 조문/항목 | 조·항·호 또는 공식 안내의 특정 항목 |
| 공포·개정 정보 | 법률번호·대통령령번호 등 확인 가능한 식별자 |
| 시행일 | 해당 버전의 효력 발생일 |
| 적용 종료일 | 다음 개정으로 효력이 끝난 날, 없으면 공란 |
| 적용 기준일 | 사건의 증여일·상속개시일 등 |
| 공식 URL | 해당 조문·버전 또는 공식 안내로 직접 연결되는 URL |
| 확인일 | 원문을 실제로 열어 확인한 날 |
| 확인자 | 확인한 사람 또는 AI 사전검토 |
| 명확한 내용 | 원문이 직접 규정하는 내용 |
| 해석 필요 | 사실판단·평가·실무 해석이 필요한 부분 |
| 상태 | 확인 / 불일치 / 연혁 재확인 / 미확인 |

[공식 출처 확인표 템플릿](../assets/templates/source-verification-log.md)을 사용한다.

## 개정 전후 혼동 방지 절차

1. 사건의 과세 기준일을 먼저 고정한다.
2. 법령 원문에서 시행일과 연혁을 확인한다.
3. 과세 기준일을 포함하는 버전인지 확인한다.
4. 현재 화면의 최신 법령과 과세 기준일 버전이 다르면 두 버전을 별도 행에 기록한다.
5. 세율·공제·기한 등 계산 파라미터는 적용 버전 행의 `source_id`에 연결한다.
6. 개정안·보도자료는 시행 법령과 구분하고, 시행 여부가 확인되기 전에는 계산값으로 사용하지 않는다.

## 계산기 전달 규칙

법률 파라미터마다 다음 데이터가 있어야 한다.

- `effective_from`, 필요시 `effective_to`
- `verified_on`
- `source.authority`
- `source.law_or_guidance`
- `source.article`
- `source.url`

공식 URL을 열지 못했거나 시행일을 확인하지 못하면 그 파라미터는 계산 파일에 넣지 않는다. 이 경우 현재 세율·공제·세액공제·신고기한을 확정하지 말고, 확인이 필요한 쟁점과 계산 방법만 제시한다.

## 실패 신호

- 최신 페이지의 숫자를 과거 과세 기준일에 그대로 적용
- 조문 링크는 있으나 시행일 또는 확인일이 없음
- 법률과 시행령의 적용 버전이 서로 다른 시점임
- 검색 결과 요약문만 보고 원문을 열지 않음
- 개정안·보도자료를 시행 중인 규정으로 취급
- 공식 근거 없는 숫자에 면책 문구만 붙여 사용
