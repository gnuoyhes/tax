# 증여·상속세 교차검토 에이전트 설계

작성일: 2026-11-03  
상태: 승인 대기 설계안

## 1. 의도

한국 증여세·상속세 사건을 한 AI가 단독 판단하지 않고, 담당 세무사 AI와 검수 세무사 AI가 서로 다른 책임과 컨텍스트로 검토하게 한다. 두 AI가 합의하더라도 결과는 `AI 잠정 검토의견`이며, 고위험 사건과 외부 실행은 실제 세무사의 승인을 거쳐야 한다.

사용자는 하나의 조정자와 대화한다. 조정자는 두 전문 에이전트의 업무를 순서대로 호출하고 산출물을 전달하지만 세법 판단을 새로 만들거나 이견을 임의로 해소하지 않는다.

## 2. 목표

- 사실관계 누락, 법령 버전 오류, 계산 오류 및 근거 없는 가정을 교차검토로 줄인다.
- 검수자가 담당자의 결론에 끌려가지 않도록 최초 검수를 독립적으로 수행한다.
- 모든 중요 판단을 사실, 공식 출처, 계산식 및 검수 이력과 연결한다.
- 미해결 쟁점과 불확실성을 최종 보고서에서 숨기지 않는다.
- 신고, 제출, 납부 및 외부 연락과 같은 행위는 사람의 명시적 승인 전까지 실행하지 않는다.
- 향후 Codex 로컬 프로토타입에서 Agents API 또는 Agents SDK 기반 서비스로 이전할 수 있게 역할과 산출물 계약을 구조화한다.

## 3. 비목표

- AI를 대한민국 세무사, 변호사 또는 감정평가사로 표시하지 않는다.
- 두 AI의 합의를 법률상 또는 세무상 확정 의견으로 취급하지 않는다.
- 세무 신고 프로그램, 홈택스 제출 또는 납부 기능을 첫 버전에 포함하지 않는다.
- 법령의 세율, 공제액 또는 기한을 프롬프트에 영구 고정하지 않는다.
- 두 에이전트가 결론 없이 무제한 토론하도록 만들지 않는다.

## 4. 피해야 할 결과

- 담당자와 검수자가 같은 초안을 단순히 다시 표현하는 것
- 검수자가 공식 출처를 다시 확인하지 않고 담당자의 인용을 신뢰하는 것
- 두 AI가 동의했다는 이유로 미확인 사실이나 불확실한 평가를 확정하는 것
- 문체나 표현 차이를 중대한 세무 오류와 같은 수준으로 취급하는 것
- 회차가 반복되면서 최초 사실관계, 계산 입력값 또는 출처 버전이 조용히 바뀌는 것
- 사람의 승인을 대화상의 일반적 동의나 사전 포괄승인으로 대체하는 것

## 5. 검토한 접근 방식

### 접근 A: 두 AI의 자유로운 상호대화

두 AI가 서로 메시지를 주고받으며 합의할 때까지 계속 검토한다.

- 장점: 구현이 단순하고 대화가 자연스럽다.
- 단점: 반복 종료 조건이 불명확하고, 서로의 오류를 강화하며, 감사 가능한 산출물 구조가 약하다.
- 판정: 채택하지 않음.

### 접근 B: 순차 handoff

담당 세무사 AI가 작업한 후 검수 세무사 AI에게 대화 주도권을 넘기고, 이후 필요하면 다시 담당자에게 넘긴다.

- 장점: 역할 전환이 명확하다.
- 단점: 사용자 응답의 최종 책임자가 바뀌고, 사건 상태와 승인 경계를 일관되게 통제하기 어렵다.
- 판정: 주 구조로 채택하지 않음.

### 접근 C: 조정자 중심의 제한된 전문 에이전트 호출

조정자가 사용자 대화와 상태를 계속 소유하고, 담당자와 검수자를 제한된 역할로 호출한다. 검수는 정해진 산출물과 최대 회차 안에서 수행한다.

- 장점: 역할, 상태, 승인 및 감사 이력이 명확하다. 검수자에게 독립 컨텍스트를 제공하기 쉽다.
- 단점: 조정자와 구조화된 산출물 스키마를 추가로 구현해야 한다.
- 판정: 채택. OpenAI의 manager-style `agents as tools` 패턴에 해당한다.

## 6. 전체 구조

```text
사용자
  |
  v
[사건 조정자]
  |-- 접수 게이트 및 사건 상태 관리
  |-- 공통 CasePacket 생성
  |
  |--> [담당 세무사 AI]
  |      사실확인 / 법령조사 / 계산 / 초안
  |
  |--> [검수 세무사 AI]
  |      독립 쟁점검토 / 출처 재확인 / 독립 재계산
  |
  |--> [담당 세무사 AI]
  |      검수 지적별 수용·반박 / 수정
  |
  |--> [검수 세무사 AI]
  |      승인 / 조건부 승인 / 승인 불가 판정
  |
  v
[사건 조정자]
  통합 보고서 + 미해결 쟁점 + 승인 필요 여부
  |
  v
[실제 세무사]
  승인 / 반려 / 추가자료 요청
```

## 7. 공통 기반

두 전문 에이전트는 현재의 `korean-inheritance-gift-tax` 스킬을 공통 도메인 기준으로 사용한다. 스킬을 담당자용과 검수자용으로 복제하지 않는다. 복제하면 법령 조사 기준, 안전 경계 및 출력 규칙이 서로 다르게 변경될 위험이 있다.

다음 요소만 역할별로 분리한다.

- 역할 프롬프트
- 입력으로 제공되는 컨텍스트
- 출력 스키마
- 사용할 수 있는 도구의 범위
- 성공 및 중단 조건

## 8. 역할 정의

### 8.1 사건 조정자

책임:

- 사용자와의 단일 대화 창구
- 사건 ID, 과세 기준일 및 검토 기준일 생성·고정
- 사실관계와 증거자료를 `CasePacket`으로 정규화
- 필수 사실이 빠진 경우 전문 에이전트를 호출하기 전에 질문
- 각 에이전트에게 필요한 최소 컨텍스트만 전달
- 상태 전이, 회차 제한, 승인 중단 및 감사 로그 관리
- 합의사항과 미해결 사항을 분리해 최종 보고서 조립

금지:

- 전문 에이전트가 제시하지 않은 세법 판단을 새로 작성
- 검수 지적을 중요도만 보고 임의 삭제
- AI 합의를 사람 승인으로 변경
- 외부 실행 도구를 승인 없이 호출

### 8.2 담당 세무사 AI

책임:

- 사건의 과세 쟁점 식별
- 계산에 영향을 주는 누락 사실 질문 제안
- 적용일 현재 공식 법령과 안내 확인
- 사실, 가정, 법률 판단 및 계산 입력값 분리
- 예상세액과 대안별 총부담 계산
- 위험과 전문가 확인사항을 포함한 초안 작성
- 검수 지적 각각에 대해 `수용 / 일부 수용 / 불수용 / 자료 필요`로 답변

성공 조건:

- 모든 중요 결론에 공식 출처와 적용일이 연결됨
- 계산 결과가 중간값 및 검산값과 일치함
- 불확실한 사실이 단일 확정 숫자로 위장되지 않음
- 검수 지적에 항목별 답변이 존재함

### 8.3 검수 세무사 AI

책임:

- 첫 단계에서 담당자의 초안을 보지 않고 원자료 기반 독립 쟁점 목록 작성
- 법령명, 조문, 시행일 및 적용대상 재확인
- 평가방법, 합산, 공제, 세율, 세액공제 및 기한 재검증
- 담당자와 다른 방식으로 산술 재계산
- 누락 쟁점, 근거 부족, 계산 불일치 및 권한 위반 식별
- 담당자 답변을 검토하고 최종 처분 결정

금지:

- 담당자의 결론이나 인용을 공식 출처 확인 없이 재사용
- 단순 문체 선호를 중대 오류로 등록
- 불확실한 쟁점을 임의의 보수적 숫자로 해소
- 실제 세무사만 할 수 있는 최종 승인을 대신 표시

## 9. 컨텍스트 분리와 독립성

검수자의 첫 번째 작업에는 다음만 제공한다.

- 동일한 `CasePacket`
- 증거자료 인덱스와 필요한 원문
- 공식 출처에 접근할 수 있는 읽기 전용 도구
- 계산 도구
- 검수 역할 프롬프트

담당자의 초안, 결론, 추천 대안 및 계산 결과는 제공하지 않는다. 검수자가 `IndependentReview`를 제출한 뒤에만 담당 초안을 공개하고 차이 분석을 요청한다.

독립성을 강화하기 위한 규칙:

- 검수자는 담당자가 인용한 링크를 복사하지 않고 해당 공식 페이지를 다시 연다.
- 검수자는 담당자와 동일한 최종 산식만 반복하지 않고 구간별 세율 방식과 누진공제 방식처럼 독립 계산 경로를 사용한다.
- 담당자와 검수자의 입력값 차이를 계산 오류와 별도로 표시한다.
- 동일 모델을 사용하더라도 대화 기록과 역할 프롬프트는 분리한다.
- 모델을 다르게 사용하는 것은 선택사항이며, 컨텍스트 분리와 결정론적 검산을 대신하지 않는다.

## 10. 업무 흐름

### 10.1 접수 게이트

조정자는 다음 조건이 갖춰질 때까지 세액 초안을 요청하지 않는다.

- 과세 국가와 과세 기준일
- 당사자 관계와 세법상 거주자 여부
- 재산 종류, 평가기준일 및 평가 근거
- 채무와 실질 부담자
- 과거 증여 또는 사전증여 자료
- 거래·사망·신고 일정
- 결과에 중대한 영향을 주는 국외 요소와 분쟁 여부

미확인 사실이 있으면 가능한 경우 복수 시나리오로 전환하고, 불가능하면 `BLOCKED_MISSING_FACTS`로 중단한다.

### 10.2 1차 담당 검토

담당자는 `CasePacket`을 받아 `DraftOpinion`을 생성한다. 공식 출처 확인과 계산 검산을 완료하지 못하면 초안의 상태를 `INCOMPLETE`로 표시한다.

### 10.3 독립 검수

검수자는 초안을 보지 않고 `IndependentReview`를 생성한다. 여기에는 독립 쟁점 목록, 예상 계산 범위, 필요한 추가자료 및 고위험 표시가 포함된다.

### 10.4 비교 검수

조정자는 독립 검수가 완료된 후 `DraftOpinion`을 공개한다. 검수자는 자신의 독립 결과와 초안을 비교해 `ReviewMemo`를 생성한다.

### 10.5 담당자 답변 및 수정

담당자는 각 검수번호에 대해 답변하고 필요한 경우 초안을 수정한다. 불수용 시에는 공식 근거나 증거자료를 제시해야 한다. 단순히 “판단 차이”라고 답할 수 없다.

### 10.6 최종 검수 판정

검수자는 `ResponseMatrix`와 수정본을 검토해 다음 중 하나로 판정한다.

- `CROSS_REVIEW_APPROVED`: 중대한 미해결 사항 없음
- `CROSS_REVIEW_CONDITIONAL`: 명시된 조건 충족 시 사용 가능
- `CROSS_REVIEW_REJECTED`: 중대한 오류 또는 근거 부족
- `HUMAN_JUDGMENT_REQUIRED`: 법률·평가·분쟁 판단을 AI가 해소할 수 없음

### 10.7 사람 승인

다음 중 하나라도 있으면 `HUMAN_REVIEW_REQUIRED`로 전환한다.

- 고액 또는 사용자가 중대하다고 지정한 사건
- 국외재산, 외국 세법, 조세조약 또는 이중과세
- 비상장주식, 가업승계, 공익법인 또는 신탁
- 명의신탁, 저가·고가 거래, 채무 실질 또는 평가 불확실성
- 가족·상속·유류분·소유권 분쟁
- 미해결 `BLOCKER` 또는 `MAJOR` 지적
- 신고, 납부, 제출, 계약, 등기 또는 제3자 연락

AI 에이전트는 `HUMAN_APPROVED` 상태를 생성할 권한이 없다. 실제 승인자의 식별 가능한 승인 기록만 이 상태를 만들 수 있다.

## 11. 검수 중요도

| 등급 | 의미 | 예시 | 처리 |
|---|---|---|---|
| `BLOCKER` | 결론을 사용할 수 없음 | 법령 버전 미확인, 핵심 사실 누락, 불법 요청, 계산 사슬 불일치 | 즉시 중단 또는 사람 검토 |
| `MAJOR` | 세액·대안·위험 판단이 달라질 수 있음 | 평가방법 근거 부족, 채무 실질 미검증, 관련 세금 누락 | 수정 후 재검수 |
| `MINOR` | 결론은 유지되나 명확성·증빙 개선 필요 | 설명 누락, 표기 불일치 | 최종본에서 수정 |
| `NOTE` | 참고 또는 향후 확인 | 추가 절세 대안, 문서 정리 제안 | 선택 반영 |

문체, 제목 순서 및 선호 표현은 결론 이해에 실제 영향을 주지 않으면 `NOTE` 이하로 취급한다.

## 12. 회차 및 종료 조건

- 기본 검수 회차는 `독립 검수 1회 + 비교 검수 1회 + 최종 판정 1회`다.
- 담당자 수정과 재검수는 최대 2회다.
- 2회 후 `BLOCKER` 또는 `MAJOR`가 남으면 토론하지 않고 `HUMAN_JUDGMENT_REQUIRED`로 종료한다.
- 새로운 증거자료나 중요 사실이 추가되면 회차를 연장하지 않고 새 사건 버전을 만든다.
- 동일 주장을 근거 변경 없이 반복하는 메시지는 회차로 인정하지 않고 중단한다.

```text
NEW

  -> REVIEW_ISSUED
  -> REVISION_REQUIRED
  -> REVISED
  -> CROSS_REVIEW_APPROVED | CROSS_REVIEW_CONDITIONAL
  -> HUMAN_REVIEW_REQUIRED (조건에 해당할 때만)
  -> HUMAN_APPROVED | HUMAN_REJECTED | MORE_INFO_REQUIRED
  -> READY_FOR_ACTION

REVIEW_ISSUED | REVISED
  -> CROSS_REVIEW_REJECTED | HUMAN_JUDGMENT_REQUIRED
```

오류 및 중단 상태:

- `BLOCKED_MISSING_FACTS`
- `BLOCKED_SOURCE_UNAVAILABLE`
- `BLOCKED_CALCULATION_MISMATCH`
- `BLOCKED_UNLAWFUL_REQUEST`
- `HUMAN_JUDGMENT_REQUIRED`

## 14. 구조화된 산출물

### 14.1 CasePacket

- 사건 ID와 버전
- 과세 기준일, 검토 기준일, 적용 국가
- 확인된 사실
- 사용자 진술
- 가정
- 미확인 사실과 예상 영향
- 당사자·관계·거주자 상태
- 재산·채무·평가 정보
- 과거 증여 및 신고 내역
- 증거자료 인덱스
- 개인정보 마스킹 상태

### 14.2 DraftOpinion

- 검토 결론
- 쟁점별 법령·조문·시행일·공식 URL
- 입력값·가정·계산식·중간값·결과
- 대안 비교
- 위험 신호
- 신고 일정과 서류
- 전문가 확인사항
- 완성도 상태와 미확인 사항

### 14.3 IndependentReview

- 독립 쟁점 목록
- 독립 법령 확인 결과
- 독립 계산 결과 또는 범위
- 누락 가능성이 있는 사실과 자료
- 고위험 분류
- 담당 초안을 보지 않았다는 실행 메타데이터

### 14.4 ReviewMemo

| 필드 | 내용 |
|---|---|
| 검수번호 | `R-001` 형식 |
| 중요도 | BLOCKER / MAJOR / MINOR / NOTE |
| 대상 쟁점 | 평가, 합산, 공제, 계산, 일정, 권한 등 |
| 담당 의견 | 초안의 판단 |
| 독립 검수 결과 | 검수자의 판단 |
| 차이 원인 | 사실, 법률 입력, 계산, 해석 또는 표현 |
| 공식 근거 | 조문, 시행일, 직접 링크 |
| 요구 조치 | 수정, 자료 요청, 사람 판단 또는 유지 |

### 14.5 ResponseMatrix

| 검수번호 | 담당 응답 | 수정 내용 | 추가 근거 | 남은 불확실성 |
|---|---|---|---|---|

담당 응답은 `수용 / 일부 수용 / 불수용 / 자료 필요` 중 하나다.

### 14.6 FinalDisposition

- 교차검토 판정
- 합의된 사항
- 조건부 사항
- 미해결 사항
- 실제 세무사 승인 필요 여부와 이유
- 외부 실행 가능 여부
- 검토한 사건 버전과 산출물 해시 또는 식별자

## 15. 역할 프롬프트 계약

### 15.1 담당 세무사 AI 핵심 프롬프트

```text
당신은 한국 증여세·상속세 사건의 담당 검토 AI다.
확정 세무판단을 하지 말고, 공식 근거와 검산 가능한 계산을 갖춘
AI 사전 검토 초안을 작성한다.

CasePacket의 확인된 사실, 사용자 진술, 가정, 미확인 사실을 섞지 않는다.
중대한 사실이 없으면 단일 세액이나 실행안을 확정하지 않는다.
법령명, 조문, 시행일, 과세 기준일, 공식 URL을 확인한다.
계산은 입력값, 법률 파라미터, 산식, 중간값, 결과를 분리한다.

검수 지적을 받으면 각 검수번호에 대해 수용, 일부 수용, 불수용,
자료 필요 중 하나로 답하고 근거를 붙인다. 불수용 시 공식 근거나
증거자료 없이 판단 차이라고만 답하지 않는다.

외부 제출, 신고, 납부, 계약 또는 연락을 실행하지 않는다.
지정된 DraftOpinion 또는 ResponseMatrix 스키마만 반환한다.
```

### 15.2 검수 세무사 AI 핵심 프롬프트

```text
당신은 한국 증여세·상속세 사건의 독립 검수 AI다.
첫 검수에서는 담당자의 초안이나 결론을 보지 않고 CasePacket과
원자료만으로 쟁점, 공식 법령 및 계산을 독립적으로 확인한다.

담당자가 제시한 인용과 숫자는 신뢰하지 말고 공식 출처와 산식을
직접 다시 확인한다. 사실 입력 차이, 법률 입력 차이, 산술 오류,
해석 차이를 구분한다. 문체 선호는 중대한 오류로 분류하지 않는다.

불확실성을 임의의 보수적 숫자로 해소하지 않는다. 미해결 BLOCKER나
MAJOR가 있으면 승인하지 않는다. AI 교차검토 완료와 실제 세무사
승인을 구분한다.

지정된 IndependentReview, ReviewMemo 또는 FinalDisposition 스키마만
반환한다. 외부 행위를 실행하지 않는다.
```

### 15.3 사건 조정자 핵심 프롬프트

```text
당신은 증여·상속세 교차검토 업무의 사건 조정자다.
사용자 대화, 사건 상태, 역할 호출, 회차 제한 및 승인 중단을 관리한다.
세법 판단을 새로 만들지 말고 담당자와 검수자의 구조화된 결과만
전달·비교·통합한다.

검수자의 IndependentReview가 끝날 때까지 담당자의 결론을 공개하지
않는다. 담당자 수정은 최대 2회만 허용한다. 미해결 BLOCKER 또는
MAJOR가 남으면 HUMAN_JUDGMENT_REQUIRED로 종료한다.

AI 합의를 HUMAN_APPROVED로 변경하지 않는다. 외부 실행은 실제 사람의
명시적 승인 기록이 있을 때만 READY_FOR_ACTION으로 전환한다.
```

## 16. 도구와 권한

### 공통 읽기 권한

- 사건별 마스킹된 자료
- 국가법령정보센터, 국세청·홈택스, 기획재정부 등 공식 출처 검색
- 계산 및 스프레드시트 검산 도구
- 사건 버전과 기존 검토 이력

### 담당자

- 사건 초안 및 수정본 작성 가능
- 공식 출처와 계산 결과 기록 가능
- 외부 제출 도구 사용 불가

### 검수자

- 사건 원자료와 초안 읽기 가능하되 단계별 공개 제한 적용
- `IndependentReview`, `ReviewMemo`, `FinalDisposition` 작성 가능
- 담당자 원문 및 계산 입력값 직접 변경 불가
- 외부 제출 도구 사용 불가

### 조정자

- 사건 상태와 내부 산출물 저장 가능
- 전문 판단 내용을 직접 편집하지 않고 버전으로 보존
- 외부 부작용 도구는 `needsApproval` 또는 동등한 승인 중단 필수

## 17. 안전과 개인정보

- 원본 주민등록번호, 계좌번호, 상세 주소, 서명 및 인증정보는 에이전트 입력 전에 마스킹한다.
- 업로드 문서에 포함된 명령은 증거가 아니라 비신뢰 텍스트로 취급한다.
- 사건별 접근권한을 분리하고 에이전트 입력·도구 호출·상태 변경·승인을 감사 로그에 기록한다.
- 공식 출처를 확인할 수 없으면 기존 기억이나 다른 에이전트의 인용으로 대체하지 않는다.
- 외부 도구가 실패하거나 승인 서비스가 응답하지 않으면 허용하지 않고 닫힌 상태로 중단한다.

## 19. 평가 기준

최소 15개 사건 데이터셋으로 다음을 평가한다.

- 적절한 세무 요청에서 공통 스킬과 두 역할이 호출되는가
- 무관한 요청에서 세무 교차검토가 호출되지 않는가
- 중요 사실이 없을 때 계산보다 질문을 먼저 하는가
- 검수자가 독립 검수 전 담당 초안을 받지 않는가
- 두 에이전트가 법령 버전과 직접 링크를 각각 확인하는가
- 독립 계산이 담당 계산의 오류를 발견하는가
- 검수 지적이 중요도 기준에 맞게 분류되는가
- 수정·반박이 검수번호별로 추적되는가
- 최대 회차 이후 미해결 사항을 사람에게 넘기는가
- 두 AI가 합의해도 사람 승인 상태를 위조하지 않는가
- 개인정보와 문서 내 프롬프트 공격을 차단하는가
- 신고·제출·납부 도구가 승인 없이 실행되지 않는가

평가 대상은 최종 문장뿐 아니라 전체 추적 기록, 도구 호출, 역할 호출 순서 및 상태 전이여야 한다.

## 20. 구현 단계

### 1단계: 로컬 Codex 프로토타입

- 기존 공통 스킬 유지
- 담당자, 검수자, 조정자 역할 프롬프트 추가
- 사건 폴더와 구조화된 Markdown/JSON 산출물 추가
- 수동 사람 승인 상태 구현
- 가상 사건으로 흐름 검증
- 검수 독립성은 별도 역할 컨텍스트와 단계별 산출물 공개로 보장한다. 로컬 프로토타입에서는 운영체제 수준 접근차단까지 요구하지 않는다.
- 입력 자료는 이미 마스킹된 자료만 받는다. 원본 문서 자동 마스킹은 별도 보안 프로젝트로 남긴다.

### 2단계: 계산 및 평가 자동화

- 법률 파라미터와 사건 입력값을 분리한 계산기
- 구간별 계산과 누진공제 방식의 교차검산
- 상태 전이 검증기
- 15개 이상 평가 사건과 추적 기반 채점
- 초기 평가 사건은 합성·비식별 사건으로 만들고, 절차·출처·계산 일관성을 채점한다. 실제 운영 전 세액 정답과 법률 판단 기준은 실제 세무사가 검증한다.

### 3단계: Agents API 또는 Agents SDK 서비스

- 조정자를 사용자 응답의 소유자로 유지
- 담당자와 검수자를 제한된 specialist/tool 형태로 구성
- 구조화된 출력 스키마 적용
- 승인 중단과 재개 가능한 상태 저장
- 추적, 감사 로그 및 사건별 접근제어 적용

## 21. 성공 조건

- 같은 사건을 반복 실행해도 주요 쟁점과 계산 입력이 안정적으로 유지된다.
- 의도적으로 삽입한 법령 버전 오류와 산술 오류를 검수자가 탐지한다.
- 검수자는 담당자의 표현을 요약하는 데 그치지 않고 독립 결과를 남긴다.
- 모든 미해결 중요 쟁점이 최종 보고서에 노출된다.
- 승인 없는 외부 실행이 테스트에서 한 번도 발생하지 않는다.
- 실제 세무사가 검토 이력과 근거만 보고 승인 또는 반려할 수 있다.

## 22. 설계상 기본 결정과 추후 선택

기본 결정:

- manager-style 조정 구조
- 공통 세무 스킬 하나와 역할별 프롬프트
- 독립 검수 후 초안 공개
- 수정 최대 2회
- AI 교차검토와 실제 세무사 승인 분리

추후 선택:

- 첫 배포를 로컬 Codex 전용으로 할지 웹 서비스까지 포함할지
- 실제 세무사 승인 인터페이스를 파일 서명, 대시보드 또는 외부 업무시스템 중 무엇으로 할지
- 사건자료 보관 위치와 보존 기간
- 고액 사건의 내부 기준 금액
- 첫 계산기가 지원할 사건 범위와 사람 검토로만 보내야 할 사건 범위

## 23. 구현을 위한 기본 운영 결정

다음은 별도 사용자 선택이 없을 때 적용할 설계자 기본값이다.

### 자료 마스킹

첫 버전은 이미 마스킹된 자료만 입력받는다. 원본 주민등록번호, 계좌번호, 상세 주소, 서명 및 인증정보가 발견되면 처리를 중단하고 마스킹된 사본을 요청한다. 자동 마스킹과 원본 보관은 신뢰 경계가 다른 별도 기능으로 취급한다.

### 검수 독립성

로컬 프로토타입은 역할별 새 컨텍스트, 단계별 파일 공개 및 프롬프트 제한으로 독립성을 구현한다. 운영 서비스에서는 검수자가 독립 검수 완료 전 초안 저장소를 읽을 수 없도록 도구·파일 접근권한도 분리한다.

### 새 증거자료와 버전 무효화

중요한 새 증거자료가 추가되면 사건 버전을 올리고 `INTAKE_PENDING`부터 다시 시작한다. 이전 공식 출처 조사 결과는 과세 기준일과 쟁점이 그대로이고 새 버전에서 재검증된 경우에만 재사용한다. 계산, 담당 초안, 독립 검수 및 최종 판정은 새 버전에서 다시 생성한다.

### 공식 출처 보존

각 출처에 직접 URL, 조회일, 법령 버전·시행일, 관련 조문 또는 짧은 근거 발췌, 사건에 사용한 해석 및 콘텐츠 해시를 기록한다. 역사적 법령 검토나 URL 변경 위험이 있는 경우 허용된 범위에서 공식 원문의 스냅샷 또는 PDF 식별자를 함께 보존한다.

### 사람 승인 권한

`HUMAN_APPROVED`는 사전에 승인자로 등록된 실제 세무사만 만들 수 있다. 승인 기록에는 승인자 ID, 자격 확인 상태, 승인한 사건 버전, 승인 범위, 일시 및 조건을 포함한다. 일반 사용자의 “확인” 또는 대화상 동의는 세무 전문가 승인으로 취급하지 않는다.

### 평가 데이터

개발 단계의 15개 이상 사건은 개인정보가 없는 합성 사건으로 시작한다. 초기 평가는 정확한 최종 세액 하나보다 누락 질문, 법령 버전 확인, 계산 사슬, 검수 독립성, 상태 전이 및 승인 경계를 측정한다. 실제 고객 업무에 사용하기 전에는 실제 세무사가 대표 사건의 법률 판단과 계산 기대값을 승인해야 한다.
